# 에메랄드 테마와 태그 탐색

사용자가 준 다크 UI 참고 이미지에 맞춰 primary를 에메랄드로 바꾸고, 사이드바 하단을 정리하며 태그 전용 화면을 만든다. push·운영 배포·사용자 데이터 변경은 하지 않는다.

## 디자인·범위

- 기존 제품 설계서가 제품 맥락의 기준이다. 새 제품 정의나 별도 브랜드 문서는 만들지 않는다. 회색 바탕은 유지하며 주 버튼·선택·포커스만 에메랄드를 쓴다. 짙은 버튼과 밝은 강조 글씨의 역할을 나눠 대비를 확인한다.
- 하단 탐색은 첫 행 「할 일 / 캘린더」, 둘째 행 「휴지통 / 태그」의 2×2 그룹. 로그아웃은 그 아래 별도 행의 중립 outline 버튼. 모바일 44px 터치 영역과 기존 실행·저장·이탈 보호를 유지한다.
- 태그는 `/tags` 전용 화면으로 옮긴다. 태그와 메모 수, 태그별 메모 목록을 보여주고 메모를 연다. 선택은 `?tag=`에 보존한다. 기존 트리·태그 필터 유틸을 재사용하며 서버 API·파일 형식은 바꾸지 않는다.

## 파일 소유

1. 부모: `app.config.ts`, `main.css`, 검증과 기존 설계 문서/프로필 갱신.
2. sidebar_mobile: `AppSidebar.vue`만. 하단 배치와 태그 진입, 기존 개별 태그 검색 칩 제거.
3. persistent_header: `pages/tags/`만. 기존 공통 헤더 Teleport·단일 루트·태그 유틸 재사용.

새 의존성·필수 인터페이스 변경 없음. Nuxt typecheck/build는 생성 파일 충돌을 피하려고 부모가 순차 실행한다.

## 확인

- 모바일/PC, 다크/라이트에서 버튼 글씨·체크·선택·포커스가 읽히고 에메랄드 역할이 일관된다.
- 하단 네 개 탐색 항목과 별도 로그아웃이 모바일에 맞고 기존 탐색·할 일 수·메뉴 동작이 유지된다.
- 태그 목록 → 선택 → 관련 메모 → 새로고침/뒤로가기가 같은 결과를 보여준다. 대소문자 변형·중복·한글·공백·특수문자 태그의 수와 필터가 일치한다.
- loading/error/empty/없는 태그의 빈 결과가 분명하고 재시도할 수 있다.
- typecheck, 단위 테스트, build, 영향받은 로컬 UI 스모크. 실제 메모·운영 캘린더는 사용하지 않는다.

## 구현과 코드 검증 결과

- primary emerald 적용. 주 버튼과 강조 글씨의 밝기를 분리하고 중립 버튼의 기존 반전 글씨는 유지했다. Nuxt UI의 실제 클래스 병합과 빌드 CSS로 주 버튼/hover/2열 배치/44px 최소 높이를 검사했다.
- 태그 전용 `/tags`와 하단 네 개 탐색 그룹, 구분된 전체 너비 로그아웃 구현. 기존 메뉴·대기열·저장 보호와 기존 태그 검색은 유지했다.
- TagBrowser 실제 setup 코드의 필터·수·URL·날짜·loading/error/retry를 모의 트리와 Vue 메모리 라우터로 확인했다. 임시 검사 44 assertions 통과(컴포넌트 행동 40 + SFC 4). 실제 네트워크/브라우저를 실행한 검사는 아니다.

- Nuxt UI 실제 클래스 병합/빌드 CSS/대비 계산 23 assertions 통과. 명령: `node /tmp/memo-theme-validate-20261013.mjs`.
  주 버튼 글씨 대비는 라이트 약 5.14:1, 다크 약 7.26:1(설치된 Tailwind OKLCH 값을 sRGB로 계산).
