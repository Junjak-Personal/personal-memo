# 모바일 편집·사이드바 수정

사용자 실기기 피드백에 따라 표 스크롤, 가려지는 커서, 작은 메뉴 버튼, 메모 메뉴, 헤더 깜빡임을 수정한다. 운영 데이터는 변경하지 않고 push는 사용자 지시가 있을 때만 한다.

## 구현과 소유 범위

1. 부모: `app.config.ts`에서 표 래퍼에만 가로 스크롤을 적용한다. `useNativeBridge.ts`에서 포커스·선택·화면 크기 변화 후 실제 커서와 가시 영역을 비교해 필요한 만큼 부드럽게 스크롤한다. 기존 네이티브 명령 계약을 유지한다.
2. sidebar_mobile: `AppSidebar.vue`에서 로그아웃을 별도 행으로 옮기고 모바일 터치 영역을 넓힌다. 모바일의 더보기 버튼 대신 길게 누르기로 메뉴를 열고, 메모 생성·삭제·폴더 이동에 기존 저장·확인·실행 취소 흐름을 재사용한다.
3. persistent_header: `default.vue`와 기존 페이지 헤더에서 공통 패널·헤더를 레이아웃에 유지한다. 페이지별 제목·툴바·저장 상태·액션은 기존 핸들러를 보존해 전달한다.

새 의존성이나 필수 인터페이스 변경은 없다. 파일별 편집자는 하나로 제한한다.

## 수락 확인

- 넓은 표가 있는 모바일 문서에서 패널 너비와 scrollWidth가 같고 표 래퍼만 가로로 움직인다.
- 네이티브 툴바 높이만큼 화면을 줄이면 커서가 가시 영역에 들어온다. 이미 보이는 커서는 움직이지 않고 blur·페이지 이탈 뒤 예약 동작이 남지 않는다.
- 모바일 더보기 버튼이 숨겨지고 길게 누르기 메뉴가 열린다. 일반 탭·스크롤은 메뉴를 열지 않는다. 닫기 버튼은 44px 이상이다.
- 메모 메뉴의 생성·삭제·폴더 이동이 기존 확인과 저장 경로를 사용한다. 운영 데이터로 검증하지 않는다.
- 페이지 전환 전후 레이아웃 헤더 DOM이 유지되고 페이지별 제목·액션이 맞게 교체된다.
- 통합 변경에서 typecheck, 기존 단위 테스트, build를 순차 검증한다. 로컬 임시 데이터와 응답 대역으로 영향받은 UI 흐름만 확인한다.

## 수정 전 증거

- 수정 전 표: 모바일 패널 너비 390px, scrollWidth 2826px. 표 래퍼 overflow-x가 visible이었다. 래퍼에 overflow-x:auto를 적용하면 패널은 390/390px으로 돌아왔다.
- 수정 전 커서: viewport 424px에서 커서 하단 401px. Flutter 툴바에 해당하는 48px 축소 후 viewport 376px인데 스크롤이 그대로여서 커서가 가려졌다.
- 헤더는 각 페이지 안에서 120ms out-in 전환과 함께 제거·생성되고 있었다.

## 완료 결과

- 표 래퍼만 `overflow-x:auto`. 모바일 390px에서 문서 패널 390/390px, 표 래퍼 358/2810px. 표 scrollLeft=180px이어도 패널 scrollLeft=0px.
- 공통 헤더와 패널을 레이아웃에 유지하고 각 페이지 제목·툴바·액션만 Teleport로 채운다. 메모 → 할 일 → 캘린더 → 휴지통 → 메모 동안 82프레임에서 헤더가 제거되지 않았고 opacity 최솟값은 1이었다. 모바일 브라우저 툴바는 헤더 101px에 포함되고 네이티브에서는 64px. 데스크톱 캘린더는 900px 화면 아래까지 채우며 내부 overflow-y:auto를 유지했다. 월 이동 버튼도 동작했다.
- 네이티브 채널을 로컬에서 대역으로 연결해 424→376px 화면 축소를 확인했다. 커서 하단 401→360px, scrollTop 313→354px. 부드러운 이동의 중간 위치 5개를 관측했고, 이미 보이는 커서는 추가로 움직이지 않았다. blur·페이지 이탈 후 브리지가 제거됐다.
- 모바일 메뉴 열기·닫기·폴더 펼침을 44px 터치 영역으로 조정하고 더보기 버튼을 숨겼다. 길게 누르기(700ms)로 메뉴가 열리고, 움직이면 대기가 취소됐다. 메뉴를 연 뒤 손을 떼도 메모가 열리지 않았다. PC 더보기 메뉴는 유지했다.
- 로그아웃은 탐색 링크 아래 구분된 행의 outline 버튼으로 옮겼다.
- 메모의 「여기에 새 메모」는 같은 폴더에 파일을 만들었다. 이동은 3초 대기 후 API·실제 임시 파일 이동을 확인했다. 다른 메모 삭제 시 현재 문서가 유지되며 사이드바는 닫혀 되돌리기를 누를 수 있다. 삭제 → 휴지통 파일 → UI 되돌리기 → 실제 파일 복원 → 전체 새로고침·재진입까지 확인했다.
- 이동창의 현재 폴더 초기화를 보장하고, 사이드바의 PC/모바일 슬롯이 대화창을 중복으로 생성하지 않도록 대화창을 슬롯 밖에 한 번 배치했다. 이동창 DOM은 1개였다.
- 검증: `pnpm typecheck` exit 0, `pnpm test` 15파일/143개 통과, `pnpm build` exit 0, `git diff --check` 통과. Nuxt 생성 파일을 공유하는 typecheck/build는 순차 실행했다. 브라우저 런타임 오류는 없었다.
- API·파일 검증은 `/tmp/memo-mobile-integrated-20261008-*`의 임시 데이터와 로컬 전용 로그인으로 진행했다. 운영 서버·메모·캘린더·비밀번호는 건드리지 않았다. push·배포는 하지 않았다.
- 데이터 처리 리뷰: 기존 인증된 API·휴지통·구조 대기열만 재사용하며 메모 ID는 URL 인코딩한다. 열린 메모를 지우기 전 저장 결과를 확인하고 실패하면 삭제하지 않는다. 서버 계약·인증·권한은 변경하지 않았다.
