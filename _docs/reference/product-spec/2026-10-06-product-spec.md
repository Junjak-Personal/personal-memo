# personal-memo — 개인 마크다운 메모

나만 쓰는 메모 앱. N100 의 폴더에 `.md` 파일로 저장하고, 날짜를 넣은 메모는 구글 캘린더의
전용 캘린더에 일정으로 만든다. PC 는 브라우저, 아이폰은 Flutter 웹뷰 껍데기.

표기: **확정** = 사용자 결정 · **실측** = 확인함 · **미확인** = 스파이크(§15)에서 확인할 것.

## 3. 저장 구조

```
{NUXT_DATA_DIR}/
  memos/
    업무/
      회의록.md
      assets/
        01JB7X….jpg
    개인/
    .trash/
      업무/회의록.md        ← 원래 상대경로를 유지한 채 이동
```

### 3.1 메모 파일

```markdown
---
id: 01JB7W…            # ULID. 파일 이름·위치가 바뀌어도 그대로
title: 회의록
created: 2026-10-06T21:03:00+09:00
updated: 2026-10-06T21:10:00+09:00
date: 2026-10-10        # 선택
date_end: 2026-10-12    # 선택. 끝 날짜 포함. date 없이 단독으로 오지 않는다
tags: [업무, 회의]      # 선택 (2026-10-07)
---
본문
```

- 앱이 아는 키는 위 7개다. **모르는 키는 지우지 않는다** — 다른 도구가 넣은 `aliases` 등은
  저장할 때 그대로 남긴다. 키 순서도 가능한 한 유지한다. 한 줄 목록은 손으로 쓰는 모양(`[a, b]`)으로 쓴다.
- **태그 (확정 2026-10-07)**: frontmatter `tags`. 읽을 때는 한 줄 목록·블록 목록·`tags: a, b` 문자열을 다 받고
  앞쪽 `#` 을 뗀다. **바뀌었을 때만** 고쳐 쓴다 — 밖에서 쓴 모양·주석이 그대로 남는다. 새로 쓸 때는 `tags: [업무, 회의]`,
  비우면 키를 지운다. 수정 요청에 `tags` 가 없으면 파일의 태그를 그대로 둔다 (옛 화면이 보낸 저장이 태그를 지우지 않게).
  최대 30개, 하나 50자. 입력칸은 공백·쉼표·Enter 로 끊는다 — 앱에서 만든 태그에는 공백이 없다.
  규칙은 `shared/utils/tags.ts` 하나를 서버·화면이 같이 쓴다.
- 구글 일정 ID 는 파일에 두지 않는다 (§8.2).
- 생성일은 `created` 에서만 읽는다. 파일 시스템 `birthtime` 은 복사·복원·Docker 볼륨에서 바뀌거나 비어 있다.
- 파일명 = 제목. 금지 문자(`/`, `\`, NUL, 앞뒤 공백, `.` 시작)는 치환한다. 같은 폴더에 같은 이름이 있으면
  `회의록 (2).md`. **앱에서 제목을 바꿨을 때만** 파일명도 바꾼다 — 밖에서 지은 이름(`meeting.md`)을
  앱에서 한 번 저장했다는 이유로 바꾸지 않는다.

### 3.2 앱 밖에서 만든 파일

`id`/`created` 가 없는 `.md` 도 목록에 나온다. 서버는 그 파일을 고쳐 쓰지 않는다 —
**서버가 사용자 파일을 쓰는 경우는 「앱에서 저장」뿐이다.**

- 그 전까지 식별자는 상대경로.
- 앱에서 처음 저장할 때 `id`, `created`(그 시각)를 붙인다.
- `created` 가 없으면 캘린더의 「생성」 표시에서 빠진다. 목록 정렬은 mtime 으로 한다.
- **같은 `id` 가 둘**(밖에서 `cp` 로 복사)이면 이미 그 id 를 갖고 있던 파일이 계속 갖고, 처음 보는 경우엔
  mtime 이 오래된 쪽이 갖는다. 나머지는 경로 id 로 열리고 앱에서 저장하면 새 id 를 받는다.
  경로 순서로 정하면 `원본 사본.md` 가 `원본.md` 의 id 를 빼앗는다 (테스트로 잡음).
- frontmatter 가 깨진 파일은 목록에 「읽지 못함」으로 나오고, 앱에서 저장하면 422 로 거부한다.

### 3.3 쓰기 규칙

- **경로 검사**: 모든 입력 경로를 `memos/` 기준으로 resolve → realpath → 루트 접두사 확인.
  `..`, 절대경로, 루트 밖을 가리키는 심볼릭 링크를 거부한다.
- **원자적 쓰기**: 같은 폴더의 임시 파일에 쓰고 rename 한다. 쓰다가 죽어도 반쪽 파일이 남지 않는다.
- **충돌 감지**: 저장 요청에 `baseVersion`(읽을 때 받은 내용 해시)을 보낸다. 디스크의 현재 해시와 다르면 409.
  다른 기기의 앱이 고쳤든 vim 으로 고쳤든 같은 경로로 잡힌다.
- **예약 이름**: `assets`, `.trash` 는 폴더 이름으로 못 쓴다. 폴더 트리에서도 숨긴다.

### 3.4 삭제·휴지통

- 메모 삭제 → `.trash/<원래 상대경로>` 로 이동. 이미지는 그대로 둔다.
- 복원 → 원래 위치로. 이름이 겹치면 `(2)`.
- 휴지통 비우기 → `.md` 를 지운 뒤, 어떤 메모(휴지통 포함)도 참조하지 않는 이미지를 지운다.
- **자동 비우기 (확정 2026-10-07)**: 휴지통에 들어간 지 **30일**이 지난 메모를 서버가 지운다 — 시작 10초 뒤, 그 뒤 하루 한 번
  (`server/plugins/trash-purge.ts`, `MemoStore.purgeTrash`). 들어간 시각은 mtime(앱이 휴지통에 넣을 때 그 시각으로 바꾼다).
  지운 뒤 쓰지 않게 된 이미지와 빈 폴더도 정리한다. 앱 밖에서 `mv` 로 `.trash/` 에 넣은 파일은 마지막 수정 시각이 기준이라
  더 일찍 지워질 수 있다. 백업(매일, 14일)에 `.trash` 가 들어가므로 지운 뒤에도 2주는 되살릴 수 있다.
  휴지통 화면에 「n일 뒤 자동 삭제」 (`shared/utils/trash.ts` 의 기간을 서버와 같이 쓴다).
- 폴더 삭제 → `.md` 가 하나도 없을 때만. 남은 `assets/` 의 이미지를 어디서든 참조하고 있으면 거부.
- 폴더 이동 → 다른 폴더 안이나 최상위로 통째로 옮긴다(`POST /api/folders/move`). 자기 자신·하위 폴더 안으로는
  거부, 같은 이름이 있으면 409. 안의 `assets/` 가 같이 가므로 폴더 안의 상대경로 이미지는 그대로 맞는다.

## 4. 이미지

- 본문에는 `![](assets/01JB7X….jpg)`. 공식 문법 + 상대경로라 다른 도구에서도 보인다.
- 파일명은 ULID. 한 번 쓰면 바꾸지 않는다.
- **업로드**: `<input type=file accept="image/*">`, PC 는 붙여넣기·드래그도 받는다. 브라우저에서 긴 변 2048px
  JPEG 로 줄여서 올린다 (pic-blog `app/utils/resize.ts` 방식). 원본은 보관하지 않는다.
- 허용 형식: jpeg, png, gif, webp. 확장자가 아니라 파일 앞부분 바이트(magic bytes)로 판별한다.
  **SVG 거부** — 스크립트를 품을 수 있고, 같은 출처에서 열리면 XSS 가 된다.
- **화면 표시**: 에디터 주소가 `/m/{id}` 라서 상대경로로는 이미지가 열리지 않는다. Image 노드 속성에는
  상대경로를 그대로 두고 `renderHTML` 에서만 `/api/files/<폴더>/assets/<파일>` 로 바꾼다. 저장되는
  마크다운에 서버 주소가 섞일 여지를 없앤다. (S3)
- `/api/files/*` 는 로그인 필요. 응답은 `Cache-Control: private, max-age=31536000, immutable` — 이름이 안 바뀌므로.
- **메모 이동**: 참조하는 이미지를 대상 폴더의 `assets/` 로 옮긴다. 다른 메모도 같은 이미지를 참조하면
  옮기지 않고 복사한다.
- **다른 폴더의 이미지를 붙여넣을 때 (확정)**: 상대경로로 되돌릴 수 없어 화면 주소(`/api/files/…`)가 남는다
  (스파이크 S3). 붙여넣는 순간 그 이미지를 받아 이 메모 폴더의 `assets/` 로 다시 올린다 —
  「메모의 이미지는 항상 같은 폴더의 assets/ 에 있다」가 예외 없이 지켜진다.
- iOS 웹뷰의 파일 입력은 HEIC 를 JPEG 로 바꿔서 준다. pic-blog 실측으로 1장 대기 약 3.5초다.
  메모에 몇 장 붙이는 용도라 네이티브 피커는 만들지 않는다.

## 5. 인덱스와 외부 수정

파일 감시(inotify/chokidar)는 쓰지 않는다. **stat 재스캔** 하나로 처리한다.

- 서버 메모리의 인덱스: `id → { 경로, title, created, updated, date, date_end, 본문, mtime, size }`.
- 재스캔 = `memos/` 전체를 stat → mtime·size 가 바뀐 파일만 다시 읽는다. 사라진 파일은 인덱스에서 뺀다.
  같은 `id` 가 다른 경로에 나타나면 「이동」으로 본다.
- 재스캔 시점: 서버 시작, 목록·검색·캘린더 요청 직전, 5분마다 (§8.3 구글 대조용).
- 메모 열기는 인덱스가 아니라 **파일에서 직접** 읽는다. 열린 내용은 항상 최신이다.
- 앱 안에서 저장한 것은 즉시 인덱스에 반영한다.

감시를 쓰지 않는 이유: 필요한 건 「인덱스가 낡지 않는 것」이고, 요청 직전 stat 비교로 충분하다.
감시를 쓰면 편집기의 저장 방식(vim 의 임시 파일 + rename), 이벤트 폭주, 놓친 이벤트를 따로 다뤄야 하고,
결국 놓친 것을 메우는 재스캔도 필요해진다.

**재스캔 시간 (실측 2026-10-07, 실제 `MemoStore`, 맥 M4 Pro)**: 메모 3,000개 — 첫 목록 213ms, 이후 목록(변경 없음) 24ms,
5개 바뀐 뒤 26ms, 검색 29ms. 10,000개 — 같은 순서로 470ms, 71ms, 86ms, 74ms. 모든 요청이 재스캔을 포함한 값이다.
**미확인**: N100 에서의 값 (배포 뒤 잰다). 스파이크 S6 는 별도 벤치 스크립트로 잰 값이다.

## 6. API

```
POST   /api/auth/login | logout
GET    /api/tree                         폴더 트리 + 메모 메타 (휴지통 제외)
GET    /api/memos/:id                    본문 + 메타 + version(해시)
POST   /api/memos                        { folder, title, content, date?, date_end? }
PUT    /api/memos/:id                    { title, content, date?, date_end?, baseVersion } — 불일치 409
POST   /api/memos/:id/move               { folder }
DELETE /api/memos/:id                    → .trash
POST   /api/trash/:id/restore
DELETE /api/trash                        비우기
POST   /api/folders                      { parent, name }
PATCH  /api/folders                      { path, name }   이름 변경
DELETE /api/folders                      { path }         빈 폴더만
POST   /api/memos/:id/images             multipart → { src: "assets/<ulid>.jpg" }
GET    /api/files/<상대경로>              이미지
GET    /api/search?q=                    제목 + 본문
GET    /api/calendar?from=&to=           { created: [...], scheduled: [...] }
GET    /api/calendar/sync                구글 동기화 상태 (§8.3)
POST   /api/calendar/sync                { allowMassDelete? } 지금 대조 → 상태
GET    /api/health
```

`:id` 는 ULID. `id` 가 없는 파일(§3.2)은 상대경로를 인코딩한 값.

## 7. 에디터

### 7.1 마크다운

- CommonMark + GFM (표, 체크리스트, 취소선). `markedOptions: { gfm: true }` 는 UEditor 기본값이다.
- 🔴 UEditor 기본 확장에는 체크리스트·표가 없다. 그대로 쓰면 체크 상태가 사라지고 **표가 통째로 지워진다**
  (S2 실측). `TaskList`, `TaskItem({ nested: true })`, `TableKit` 을 반드시 넣는다.
- 밑줄은 `<u>text</u>` (`app/utils/editor-extensions.ts` 의 `HtmlUnderline`). Tiptap 기본 `++text++` 를 버리고,
  `<u>…</u>` 를 직접 잘라 안쪽을 마크다운으로 다시 읽는다 — 인라인 HTML 로 두면 `<u>` 안의 `**굵게**` 가
  저장할 때마다 역슬래시가 불어난다 (S2 실측).
- 왕복 결과는 스파이크 문서 S2 절. 표는 첫 저장에서 공백이 정리되고 그 뒤로 고정된다.
- 서버가 frontmatter 를 떼고 본문만 에디터에 준다. 제목·날짜는 별도 입력칸.
- **왕복 검사**: 열 때 `serialize(parse(본문))` 이 원문과 다르면(줄 끝 공백·마지막 개행 차이는 무시)
  첫 저장 전에 「앱에서 저장하면 형식이 바뀝니다」 경고 + 확인을 받는다. Tiptap 이 모르는 문법
  (각주, 수식, HTML 블록)이 저장하면서 사라지는 것을 막는다.

### 7.2 자동저장

- 입력이 멈추고 **1초** 뒤 저장 (2026-10-07 사용자 결정). 화면 이탈·`visibilitychange(hidden)` 에서는 즉시 저장.
- **제목은 5초** (확정 2026-10-07): 제목이 바뀌면 파일 이름도 바뀌므로, 치는 도중마다 파일 이름이 바뀌지 않게 입력이
  5초 멈추거나 제목 칸을 벗어날 때(Enter 포함) 확정한다. 확정 전엔 「고치는 중」. 나가기·숨김·옮기기 전엔 확정까지 해서 저장.
  (명시적 저장 버튼도 검토했으나 사용자가 자동 저장 유지로 결정.)
- **열기만 해서는 저장하지 않는다.** 에디터는 뜨면서 변경을 한 번 알린다(끝에 빈 줄 등) — 원본을 에디터로
  한 번 정리한 결과와 같으면 무시한다 (2026-10-07 실측: 무시하지 않으면 여는 순간 「고치는 중」).
- 왕복 검사는 모양만 다른 차이(표 칸 공백·구분선 대시 개수·빈 줄·기호 이스케이프 `\~`)를 걷어내고 비교한다.
  대괄호·꺾쇠 이스케이프는 남긴다 — 각주 `[^1]` → `\[^1\]` 가 잡아야 할 손실이다 (`canonicalMarkdown`).
- 저장하지 못한 채 다른 화면으로 가려 하면 막고 [다시 시도] [저장 안 하고 이동] 을 묻는다.
- 409 → 「다른 곳에서 수정됨」 안내. 버튼: [다시 불러오기] (outline) [내 내용으로 덮어쓰기] (default).
  조용히 덮어쓰지 않는다.
- 네트워크 실패면 표시를 남기고 재시도. 「저장됨」 표시는 서버 응답을 받은 뒤에만.

#### 7.2.1 오프라인 보호 — 쓰던 내용 보호만 (확정 2026-10-07)

완전 오프라인(화면 캐시, 오프라인 새 메모, 동기화)은 하지 않는다. **고친 내용을 잃지 않는 것**만 한다.

- 저장 요청을 보내기 **전에** 이 기기(localStorage `memo-draft:<id>`)에 보관하고, 서버가 받으면 지운다
  (`app/utils/memo-drafts.ts`). 응답을 기다리는 사이에 앱이 꺼져도 남는다.
- 서버에 닿지 못하면 상태가 「기기에 보관」(주황). `online` 이벤트와 30초마다 다시 보낸다.
- 그 상태로 다른 화면으로 가는 것은 막지 않는다 — 보관함(`plugins/memo-drafts.client.ts`)이 앱이 뜰 때·`online`·앱이 다시
  보일 때·1분마다 열려 있지 않은 메모의 보관 수정을 대신 저장한다.
- 🔴 **조용히 덮지 않는다**: 보관 수정의 기준 버전이 서버와 다르면(409) 충돌로 표시만 하고 남긴다. 그 메모를 열면
  「이 기기에 저장하지 못한 수정이 있습니다」 → [보관된 수정 버리기] [보관된 수정으로 덮어쓰기]. 서버가 그대로면 열 때 바로
  되살려 저장한다.
- 화면 코드(청크)를 못 받아 이동이 실패하면: 오프라인이면 그 화면에 머물고 「연결이 없어 이 화면을 열 수 없습니다」,
  온라인이면 그 주소로 다시 불러온다 (`plugins/route-chunk-error.client.ts`, `emitRouteChunkError: 'manual'`).
  Nuxt 기본값은 오프라인에서도 다시 불러와 브라우저 오류 화면(껍데기의 「연결하지 못했습니다」)으로 넘어갔다.
  🔴 브라우저는 실패한 동적 import 를 기억해 다시 연결돼도 같은 화면이 계속 실패한다 — 다시 불러오기만이 푼다 (2026-10-07 실측).
- 확인 (브라우저, 오프라인 흉내): 열어 둔 채 오프라인 수정 → 「기기에 보관」 → 연결 → 저장 · 오프라인에서 처음 가는 화면 →
  머묾 + 안내 → 연결 뒤 다시 누르면 열림 · 이미 받은 화면으로 이동 → 연결되면 보관함이 저장 · 서버 그대로면 열 때 되살림 ·
  서버가 바뀌었으면 알림 → 덮어쓰기. **폰(WKWebView)의 online/offline 이벤트는 기기에서 확인 전.**

### 8.2 일정과 메모의 연결

일정 ID 를 파일에 두지 않는다. 일정에 `extendedProperties.private.memoId = <id>` 를 심어 둔다.

- 서버가 사용자 파일을 고칠 일이 생기지 않는다 (vim 으로 열려 있는 파일을 서버가 바꾸지 않는다).
- 파일 이동·이름 변경에도 연결이 유지된다 (`id` 기준).
- `id` 없는 외부 생성 파일은 앱에서 한 번 저장해 `id` 가 붙은 뒤부터 연동된다.

### 8.3 동기화 = 대조 (단방향: 메모 → 캘린더)

전용 캘린더의 일정 전체를 한 번에 받아(`events.list`, 페이지당 최대 2500) `memoId` 로 인덱스와 맞춘다.
상태를 따로 저장하지 않으므로, 서버가 꺼져 있던 동안의 변경·실패한 재시도·vim 으로 고친 것이
전부 다음 대조에서 같은 방식으로 맞춰진다.

| 인덱스 | 캘린더 | 동작 |
|---|---|---|
| `date` 있음 | 없음 | 생성 |
| `date`/`date_end`/`title` 이 다름 | 있음 | 수정 |
| `date` 없음, 휴지통, 파일 사라짐 | 있음 | 삭제 |
| — | `memoId` 없는 일정 | 손대지 않음 (직접 만든 일정) |

- 시점: 앱에서 저장한 직후(2초 디바운스) + 5분마다 + 서버 시작 시(3초 뒤).
  저장 직후는 «캘린더에 보일 모양»(제목·date·date_end)이 마지막 대조 때 본 캘린더와 다를 때만 — 본문만 고친
  1초 자동저장이 구글을 부르지 않게. 휴지통·되살리기도 부른다. 옮기기·폴더 이름 변경은 id 가 그대로라 부르지 않는다.
- 🔴 종일 일정의 `end.date` 는 끝 날짜를 포함하지 않는다. 보낼 때 `(date_end ?? date) + 1일`.
- 🔴 **대량 삭제 차단**: 메모 파일이 하나도 없거나(휴지통 포함), 한 번의 대조에서 삭제가 **3건을 넘고** 기존 일정의
  절반도 넘으면 삭제만 미루고(생성·수정은 한다) 화면에 「보류」로 남긴다. 데이터 디렉토리 마운트가 빠진 채 서버가 뜨면
  모든 일정이 지워지는 경우를 막는다. 캘린더 화면에서 사람이 「확인하고 지우기」를 눌러야 진행한다.
  - 3건 문턱 (2026-10-07 추가): 일정이 한두 개일 때는 하나만 지워도 「절반 초과」라 날짜 하나 지우는 일까지 막혔다.
  - 휴지통을 세는 이유 (2026-10-07 스모크에서 발견): 하나뿐인 메모를 휴지통에 넣으면 활성 메모가 0개라 그 일정이
    지워지지 않았다. 폴더가 정말 빠졌다면 휴지통도 비어 있다.
- 비교는 제목·시작·끝만. 구글에서 설명·색·알림을 바꾼 것은 두고, 시간 일정으로 바꾼 것은 종일로 되돌린다
  (PATCH 로 `dateTime: null`). 같은 memoId 일정이 둘 이상이면 맞는 것 하나만 남긴다.
- 새 일정은 「한가함」(`transparency: transparent`) — 메모 일정 때문에 바쁨으로 보이지 않게.
- 일정 설명에 앱의 메모 주소(`NUXT_SITE_URL` + `/m/<id>`)를 넣는다. 비우면 설명도 비운다.
- 구글 쪽에서 일정을 고쳐도 메모에 반영하지 않는다.
- 실패해도 메모 저장은 성공으로 둔다. 문서 화면 날짜 옆에 「캘린더 반영 실패」(누르면 다시 시도), 캘린더 화면에
  이유를 보이고, 다음 대조에서 다시 시도한다. 실패 기록은 서버 메모리에만 있다 — 재시작하면 다음 대조가 다시 채운다.
- frontmatter 를 못 읽는 파일은 id 를 알 수 없어(`p:` 경로 id) 그 일정이 지워지고, 파일을 고치면 새 일정으로 다시 생긴다 (수용).
- 설정이 없으면 꺼진다 — **개발 기본값은 꺼짐**. 🔴 개발과 운영이 같은 캘린더를 쓰면 서로의 일정을 «주인 없는 일정»으로
  보고 지운다. 개발에서 시험할 때는 임시 데이터 폴더 + 별도 dotenv 로 띄운다 (아래 결과 참고).
- 코드: `server/calendar/{google,reconcile,sync}.ts`(Nuxt 없이 Vitest), `server/utils/calendar-sync.ts`(설정·싱글톤),
  `server/plugins/calendar-sync.ts`(시작·5분), 저장 API 의 `useCalendarSync()?.notify(memo)`.

**결과 (2026-10-07)**: Vitest(구글 흉내) + 실제 「메모」 캘린더 스모크 19/19 통과 — 임시 데이터 폴더, 끝나고 일정 0건 확인.
생성(끝 +1, 설명 주소, 한가함) · 수정(같은 일정 id) · 구글에서 시간 일정으로 바꾼 것 복구 · 중복 정리 · memoId 없는 일정
유지 · 날짜 지우면 삭제 · 휴지통 → 삭제 → 되살리기 → 생성 · 절반 초과 보류 → 확인 후 삭제 · 빈 폴더 보류 → 확인 후 삭제.
없는 캘린더 ID 로 띄워 「캘린더 반영 실패」 표시와 다시 시도 토스트도 확인. 스크립트: `scripts/calendar-smoke/smoke.mjs` (절차는 파일 머리 주석). 캘린더에 이미 메모 일정이 있으면 멈춘다 — 운영 캘린더 보호.

### 8.4 캘린더 화면

- 월 보기 하나. 날짜 칸에 「생성」(created 기준)과 「일정」(date ~ date_end)을 다른 모양으로 구분한다.
- 날짜를 누르면 그날의 메모 목록. 휴지통 메모는 제외.
- 템플릿 `MonthView`/`MonthWeek` 가 기간을 막대로 그린다 (S4). 가져올 때:
  - 드래그 생성·이동, 팝오버, 헤더 높이 상수 결합을 걷어낸다 — 복사보다 이 작업이 크다.
  - 어댑터: `date` → `start: 'YYYY-MM-DDT00:00:00'`, `date_end + 1일` → `end`. 날짜만 있는 문자열을
    `new Date()` 에 넣으면 UTC 로 읽혀 KST 에서 하루 밀린다.
  - 포매터 로케일 `en-US` → `ko-KR`, `+N more` 는 outline 버튼으로.
- 「생성」은 날짜 숫자 옆 점·개수로 표시한다 (확정) — 막대 3레인과 칸을 두고 경쟁하지 않는다.
- 주 시작은 **일요일** (확정). 템플릿의 `weekStartsOn: 1` 4곳을 바꾼다.

**구현 (2026-10-07)**: 템플릿을 그대로 옮기지 않았다. 템플릿 MonthView 는 5년치 주를 가상 스크롤하고 날짜 계산에
date-fns 를 쓰는데, 이 앱에는 한 달씩 넘기는 화면이면 충분하다. 격자 구조(주마다 7열 grid, 첫 줄 날짜 숫자, 막대 줄,
마지막 칸 「+N」)와 레인 배치(layoutAllDay)만 가져왔다.
- 날짜는 전부 `YYYY-MM-DD` 문자열로 계산한다 (`shared/utils/memo-date.ts` 의 addDays·weekdayOf) — Date 로 바꿀 일이 없다.
- 보고 있는 달·고른 날은 주소에 둔다(`/calendar?m=2026-10&d=2026-10-07`). 메모를 열었다 뒤로 오면 그 자리.
- 막대를 누르면 메모, 칸을 누르면 오른쪽(폰은 아래) 목록 — 「일정」과 「이날 만든 메모」. 「+N」도 그 날을 고른다(팝오버 없음).
- 막대 3줄. 폰도 같은 수 — 막대 높이만 줄인다(18px / PC 22px).
- 목록 아래에 구글 연동 상태(마지막으로 맞춘 때, 실패·보류, 지금 맞추기).
- 코드: `app/pages/calendar/_modules/` (CalendarView, CalendarWeek, CalendarDayList, CalendarSyncPanel, month-layout.ts + 테스트).

## 10. 모바일과 Flutter 껍데기

### 10.1 왜 껍데기가 있나

툴바를 키보드 바로 위에 두기 위해서다. 웹으로는 어렵다.

- iOS WKWebView 는 `interactive-widget=resizes-content` 를 지원하지 않는다 (MDN BCD: `safari_ios`,
  `webview_ios` 둘 다 false). 키보드가 떠도 레이아웃 뷰포트가 줄지 않는다.
- visualViewport 를 따라가는 방식은 pic-blog 에서 다섯 가지 접근이 실측으로 실패했다
  (`2026-08-31-ios-keyboard-findings.md`).

### 10.2 구조

- 툴바는 Flutter 위젯이다. 키보드 위 위치는 Flutter 가 잡는다.
- 버튼 (확정 2026-10-07, 가로 스크롤): `＋ 블록 메뉴` | H1 H2 H3 | 굵게·기울임·밑줄·취소선 | 링크·이미지 | 실행취소·다시실행.
  ＋ 는 웹이 `/` 를 넣어 블록 메뉴를 연다. 링크는 웹의 창(LinkDialog)으로 받는다. 이미지는 올리기 자리를 넣고
  사람이 그 자리를 누른다 — 파일 고르기는 사람의 탭 안에서만 열린다.
- 폰에서 안 되는 것: ⠿ 끌어서 옮기기(마우스를 올려야 뜸), 글자 말풍선 툴바(§7.3, iOS 메뉴와 겹침). 표 툴바는 뜬다.
- 버튼 탭 → 브리지로 명령 → 웹이 `editor.chain().focus().toggleBold().run()` 같은 명령을 실행한다.
  **서식 로직은 웹에만 있다.**
- 웹 → 네이티브: 에디터 포커스/블러(툴바 표시 여부), 현재 서식 상태(버튼 활성 표시).
- 브리지 계약은 pic-blog 규칙을 따른다: 반환 모양을 바꾸지 않는다, 새 정보는 따로 난 창으로 준다,
  페이지가 설 때마다 다시 심는다.
- pic-blog `app-ios/lib/main.dart` 에서 가져올 것: SafeArea, 콘텐츠 프로세스가 죽으면 다시 로드,
  가장자리 스와이프 뒤로가기 끔 (저장 안 된 입력 보호).
- 껍데기 밖(브라우저)에서는 웹 툴바(상단 고정)를 쓴다.
- 껍데기 색은 시스템 다크·라이트를 따르고 웹(Nuxt UI neutral)과 같은 값을 쓴다 (`Palette`) — 상태바 영역·툴바가
  웹과 다른 색이면 띠처럼 보인다.
- 첫 페이지를 못 불러오면 흰 화면 대신 「메모 서버에 연결하지 못했습니다」+ 주소 + 오류 + 다시 시도.
- 개발용 설치(`app-ios/tool/dev-install.sh`)는 맥을 `이름.local` 이 아니라 와이파이 IP 로 부른다 — 이 네트워크의
  DNS 가 `.local` 이름에 공인 IP 를 답해 흰 화면으로 멈췄다 (2026-10-07). iOS 10+ 에서 ATS 는 IP 주소에 적용되지 않는다.

### 10.3 스파이크 결과 (S1, 실기기)

1. 버튼 탭에 포커스를 잃지 않는다 — 탭 5번, blur 0건, 키보드 그대로. 버튼은 `GestureDetector` 로 받는다
   (포커스를 요청하는 위젯 금지).
2. 두 번 밀리지 않는다 — `visualViewport.offsetTop` 이 내내 0, 웹뷰 높이가 키보드를 따라 759 → 376.

→ **네이티브 툴바로 확정.** 웹 상단 고정 툴바는 브라우저용으로만 남는다.
코드: `app-ios/lib/main.dart`, 개발용 설치 `app-ios/tool/dev-install.sh` (「memo dev」, `win.jundevlog.memo.dev`).

키보드를 내리면 툴바가 사라지는 것, iOS 기본 입력 보조 막대와 겹치지 않는 것은 사용자가 기기에서 확인했다.
