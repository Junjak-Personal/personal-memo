# 본문 컬럼과 트리 새로고침

기준 SHA: `cc3f22c927e1624086751b73b140972cb89a1fa3`. `feat/editor-columns`에서 작업한다.

## 동작

- 기존 편집기 툴바와 슬래시 메뉴에서 2·3·4열 블록을 넣고 열 수를 바꾸거나 해제한다.
- 각 열에는 기존 문단·목록·사진·표를 배치한다. 열 축소·해제는 내용 순서를 보존하며, 컬럼의 중첩 삽입은 막는다.
- Markdown 안의 명시적 HTML 블록으로 구조를 저장하고 기존 스키마를 통해서만 파싱·직렬화한다. 저장 이미지 경로에 화면용 URL을 섞지 않는다.
- 편집기·공개 보기에서 같은 레이아웃을 사용하며, 좁은 화면에서는 세로로 쌓는다.
- 트리 헤더의 새로고침 버튼은 펼침·선택·스크롤·입력을 보존하면서 기존 갱신 경로를 사용한다. 실패해도 이미 받은 트리는 남긴다.

## 범위와 소유

- 코어: `editor-columns.ts`와 해당 단위 검사.
- 메뉴: 기존 `editor/items.ts` 확장.
- 통합: 공통 확장·본문 CSS·AppSidebar, 격리 브라우저 검사.
- 외부 의존성·서버 API 계약·운영 메모 형식의 임의 변환 없음. 실제 이력서의 사진 배치는 기능 검증 후 별도 사용자 편집으로 남긴다.

## 확인

1. 타입 검사·단위 검사·빌드.
2. 실제 에디터에서 삽입·열 변경·내용 보존·해제·다시 읽기와 읽기 전용 보기를 확인.
3. 이미지 상대경로, 표·목록·서식 왕복과 기존 HTML 표 회귀를 확인.
4. 격리 앱에서 새로고침 후 새 폴더 표시 및 펼침·선택·스크롤·미저장 입력 유지를 확인.

## 결과

- `VERIFY_PASS`: 전체 Vitest 59파일/631개, Nuxt 타입 검사·프로덕션 빌드 통과.
- 실제 Tiptap 브라우저 회귀 21/21 통과. 2·3·4열의 반복 저장/읽기, 이미지 상대경로·표·서식 보존, 열 축소·해제·각 단계 undo와 기존 표 회귀를 확인했다.
- 격리 Nuxt 앱에서 툴바로 2·3·4열 변경, 두 번째 열 입력·서버 저장·새로고침 후 유지, PC의 균등 열 폭과 390px 모바일의 세로 배치를 확인했다.
- 같은 합성 메모의 공개 화면에서 읽기 전용 컬럼과 이미지 로드를 확인했다. 운영 데이터에는 컬럼 구조를 쓰지 않았다.
- 트리가 열린 상태에서 API로 합성 폴더를 추가한 뒤 버튼으로 갱신했다. 새 폴더 표시와 펼침·스크롤·검색 입력·편집 중 제목·현재 메모 유지를 확인했다.
- 서버·데이터·브라우저 화면은 loopback의 격리 환경을 사용했다. 검사 서버를 종료했다. 의존성 추가 없음.
- 최초 구현은 `6ef939a`로 커밋·푸시했다. 이후 사용자가 공개 메모 UI PR #13과 함께 운영 배포를 승인하여 통합했다. `AppSidebar.vue` 충돌은 공용 `MemoTree`와 새로고침·실패 시 트리 유지 조건을 함께 보존했다.
- 통합 검증: 전체 Vitest 59파일/637개, stage 시드 7개, 타입 검사·빌드, 실제 브라우저 표·컬럼 회귀 21개 통과. 합성 공개 화면에서 컬럼·제목 선택 검색·공개 백링크를 확인했다. 운영 데이터·공개 설정은 변경하지 않는다. 운영 배포 근거는 PR #13과 해당 main Deploy 실행에서 확인한다.

## Deferred QA

- iPhone 실기기의 열 안 터치 편집·키보드 이동은 미검증이다. 모바일 폭의 브라우저 레이아웃은 확인했다.
- 트리 갱신의 네트워크 오류·재시도 실제 UI는 미검증이다. 사용하는 브라우저 드라이버가 요청 가로채기를 제공하지 않아 강제 오류를 주입하지 않았다. 구현은 기존 트리를 유지하고 오류 문구·다시 시도 버튼을 표시한다.
